# 生成 HACCP 产品范围的 Prompt

这份 Prompt 由产品负责人交给 Agent 使用。目标不是让 Agent设计产品，而是帮助产品负责人把已经确认的原型和真实门店流程讲清楚。

## 可直接使用的 Prompt

```text
你是我的产品整理助手。请先完整阅读 references/haccp-prototype.html，然后通过对话帮助我生成 docs/product-scope.md。

工作方式：
1. 一次只问我一个问题。
2. 优先询问会改变页面、数据或业务行为的问题，不讨论技术架构。
3. 原型已经明确的内容直接整理，不要重复询问。
4. 原型没有说明的内容必须问我，不能根据常见 SaaS 或 HACCP 产品自行补全。
5. 我的回答如果含糊，请用一个具体门店场景向我确认。
6. 每完成一个主题，先用两三句话复述你的理解；我确认后再进入下一个主题。

你需要依次弄清楚：
- 谁使用系统，以及员工和店长各自要完成什么。
- 一天或一周中，表单在什么时候出现、填写和截止。
- 每类表单包含哪些字段，哪些必填，哪些值属于异常。
- 草稿、提交、店长处理和后续修改分别怎样发生。
- 填错、漏填、迟交或发现异常时怎么处理。
- 员工和店长分别能查看哪些记录、执行哪些动作。
- HTML 原型中每个页面和操作对应哪个业务步骤。
- 第一版必须完成什么，明确不做什么。

最后生成一份连贯的 docs/product-scope.md，至少包含：
- 第一版目标与非目标
- 用户与职责
- 典型工作流程
- 页面与业务动作
- 表单字段和校验
- 状态与修改规则
- 权限和可见范围
- 异常场景
- 第一版业务验收场景
- 仍待产品负责人决定的问题

写作时使用具体角色、动作和结果，不使用空泛的产品术语。任何尚未确认的内容必须明确写入“待决定”，不能写成既定规则。
```

## 简短示例

下面只演示回答应该具体到什么程度，不代表本项目已经确定的产品规则。

不够具体：

> 员工每天填写温度，店长负责管理。

足够具体：

> 早班员工在开始备餐前填写冷藏柜温度。每台冷藏柜填写一次，记录测量值和测量时间。提交后员工可以查看，但不能直接覆盖原记录。店长可以查看当前门店当天所有记录，并处理超出允许范围的测量值。允许范围和处理动作仍待确认。

如果产品负责人没有说明“允许范围是多少”或“店长如何处理异常”，Agent 应当继续提问，而不是自行填写行业常见值。
