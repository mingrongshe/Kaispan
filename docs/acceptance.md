# HACCP 第一版验收标准

第一版完成表示模块已经可以独立试用，不表示已经正式接入 KaiSpan。

## 产品结果

- HTML 原型中的核心页面和交互已经成为真实功能。
- 员工可以看到、填写、保存并提交自己需要处理的表单。
- 店长可以查看当前门店的提交记录，并完成产品范围中确定的处理动作。
- 页面刷新或重新登录后，记录仍保存在 PostgreSQL。
- 有可直接使用的员工、店长演示账号和必要的演示数据。
- README 记录真实可执行的安装、migration、启动、测试和演示步骤。

`docs/product-scope.md` 中每个“第一版必须完成”条目都要对应一个看得见的页面行为或保存结果。仍待决定的问题不能由 Agent 自行补成已完成规则。

## 技术边界

- HACCP 业务数据带有 `organizationId`；门店数据同时带有 `unitId`。
- 前端只通过 NestJS API 访问业务数据。
- 员工填写和店长管理都经过后端的集中权限模块。
- 已提交记录不会被无痕物理删除。
- Prisma schema 的变化都有可重复执行的 migration。
- 仓库不包含密码、token、真实数据库连接或真实个人数据。

## 最低自动化检查

至少验证以下结果：

1. 员工可以填写并提交允许访问的 HACCP 表单。
2. 员工调用店长管理接口时被拒绝。
3. 店长可以执行产品范围中确认的管理动作。
4. 当前 organization 的用户不能读取或修改另一个 organization 的记录。
5. 当前 unit 的用户不能读取或修改另一个 unit 的记录。
6. 记录提交或经店长处理后，状态和操作人正确保存在 PostgreSQL。

演示页面可以只使用一个公司和一家门店。隔离测试在测试数据库中额外创建第二个 organization 和 unit，仅用于证明数据不会串到另一家公司或门店。

权限检查可以使用 service 或 API 测试。organization/unit 隔离和持久化结果必须使用真实 PostgreSQL 验证，mock 测试不能替代这一项。

代码初始化后，项目至少提供以下脚本，README 写明准确运行方式：

- `pnpm typecheck`
- `pnpm test`
- `pnpm test:integration`
- `pnpm build`

## 人工完整流程

按照 README 走完一次：

```text
员工登录
→ 打开需要填写的表单
→ 保存并提交
→ 刷新后记录仍存在
→ 店长登录并看到该记录
→ 店长执行确认的管理动作
→ 员工看到最终状态
```

记录实际通过的命令和人工步骤，并列出尚未验证的内容。不需要把长测试日志复制进本文。

## 第一版不能代表的结果

第一版通过后，只能说明独立 HACCP 模块达到可试用状态，不能宣称：

- 已接入 KaiSpan。
- 已通过 KaiSpan 完整 RBAC 或 tenant isolation gate。
- 已通过自动化浏览器 E2E。
- 已达到生产发布或合入条件。
